# 동작 구조

GUI 스레드는 입력, 모의 창 그리기, 결과 표시만 담당한다. 캡처·템플릿 판독·안정화·Monte Carlo는 하나의 QThread 파이프라인에서 순차 처리한다. 대기 프레임 큐나 중첩 계산을 만들지 않는다. 계산이 캡처 주기보다 길면 다음 캡처를 지연시키며 UI는 계속 응답한다. Event 기반 취소/대기와 상한이 있는 반복 수로 부하를 제한한다. 라이브 플레이용 지연 보장은 없다.

MockSource는 잠금으로 상태를 스냅샷하고 소스 revision을 증가시킨다. Worker는 이미지 해시로 중복 판독/계산을 피하되 같은 프레임도 안정화 횟수에 포함한다. 입력 실패 시 안정화를 초기화하고 두 번의 새 유효 관측을 요구한다. GUI는 설정 및 소스 revision이 다른 계산 결과를 버린다. 정지는 UI에서 스레드 종료를 동기 대기하지 않는다. 종료 요청은 계산을 취소하고 worker 종료 후 창을 닫는다.

Windows mss 경로는 GUI가 생성한 자기 프로세스의 모의 HWND만 사용한다. 전경 상태와 현재 Win32 client 사각형을 프레임마다 확인한다. ROI는 화면 전체에 대한 절대 좌표가 아니라 모의 창 이미지의 정규화 좌표다. Qt는 기본 고해상도 DPI 처리를 사용한다. 자체 테두리를 검출해 크기를 정규화하고, 헤더를 검사한 뒤 고정 슬롯의 카드/문자를 판독한다. 분수 배율은 두 가지 nearest-neighbor 매핑과 area 보간 중 표식 일치도가 높은 것을 선택한다. 심하게 축소되거나 일부가 가려진 화면, 일반 사이트 화면을 복구/추측하지 않는다.

미지원 입력과 인식 실패는 None+errors로 표현한다. 부분적으로 읽힌 필드를 종합해 가짜 GameState를 만들지 않는다. OptionalOCR Protocol은 확장점이며 기본 백엔드는 없다. 모의 인식기는 저장소 자체 fixture를 사용한다. 실제 인식기는 사용자가 명시적으로 선택한 스크린샷으로 보정한다. 화면 캡처를 디스크에 자동 저장하지 않는다. 사이트 통신 모듈이나 입력 자동화 모듈은 없다.

Monte Carlo는 알려진 카드를 제거한 덱에서 상대의 각 범위를 독립 균등 추출하고, 상대끼리 중복되면 **전체 배정**을 거부한다. 이후 남은 보드를 균등 추출한다. 순차적으로 범위를 줄이는 방식의 배정 편향을 피한다. 상대 범위는 가중치 없는 실제 카드 조합의 합집합이다. 알려진 카드로 막힌 조합은 제거한다. 너무 제약된 범위는 오류로 종료한다. equity는 매 표본 팟 지분의 평균, 표준오차는 해당 지분의 표본 모멘트 기반 근사치다. 강제 전수 열거가 아니므로 작은 확률 사건은 누락될 수 있다.

전략 엔진의 숫자는 조건부 계산이다. 상대가 콜한 경우의 equity를 무작위 핸드 상대 equity로 대신하지 않는다. 베팅 EV는 명시적 전체 폴드 확률과 콜 조건 equity가 주어진 헤즈업 종료 모델에서만 산출한다. 다자간 베팅/사이드 팟과 불명인 행동 이력을 근거로 최적 행동을 확정하지 않는다.


# 0.2: 실제 화면 선택과 보정

사용자의 요청으로 실제 데스크톱 캡처 경로를 추가했다. ReferenceCapture는 앱이 숨겨진 뒤 선택된 모니터의 보정용 한 프레임을 작업 스레드에서 캡처한다. CalibrationDialog에서 테이블과 개별 카드·금액의 상대 좌표 및 정답 카드 샘플을 지정한다. DesktopRegionCapture는 이후 테이블 사각형만 mss로 캡처한다. 모니터 배치/해상도가 바뀌면 조용히 다른 영역을 읽지 않고 재보정을 요구한다. 사이트에 연결하거나 브라우저를 제어하지 않는다.

ScreenRecognizer는 사용자 샘플과 카드 에지 템플릿을 비교한다. 충분히 일치하고 후보 간 차이가 있을 때만 채택한다. 빈 보드 샘플은 슬롯마다 분리한다. 모든 52장이나 사이트별 배치를 내장하지 않으므로 미등록 카드가 나오면 추가 샘플이 필요하다. 불확실한 값을 추정해 채우지 않는다. 숫자는 선택적 Tesseract 실행 파일로 판독하며 원본/2배 이미지 모두 충분한 신뢰도와 동일한 결과를 요구한다. 그래도 OCR의 정답을 보장하지 않으므로 실화면과 대조가 필요하다. 프로세스별 타임아웃 2초를 둔다.

실제 모드의 변경 검사는 보정된 카드·숫자 픽셀만 해시해 타이머·채팅·아바타 애니메이션 때문에 재계산되지 않도록 한다. 계산 후에도 중요 픽셀을 다시 확인한다. 기본 목표 주기는 1000ms이며 OCR/MC가 이를 초과하면 다음 프레임을 늦춘다. 고정 1Hz 완료나 무손실 프레임 처리를 보장하지 않는다.

상대 수/포지션은 프로필을 저장할 때의 수동 가정이다. 스택은 개별 OCR 영역이 있으면 자동 갱신, 없으면 수동 가정을 유지한다. 보정 파일에는 좌표·샘플만 저장하고 `.local/`은 Git/배포 ZIP에서 제외한다. 기본 PokerNow 프로필은 실제 화면 자료가 없어 포함하지 않았다.


# 0.3: 행동을 먼저 보여주는 대시보드

Dashboard가 플레이 화면을 담당하고, 설정/수동 수정/상세 계산을 QTabWidget으로 분리한다. 시작·중지·입력 모드는 탭 밖에 유지한다. strategy.guidance는 새로운 상대 모델을 가정하지 않고 기존 콜 EV/팟 오즈를 조건부 문장으로 변환한다. 비용 0이면 체크 가능, equity의 MC 근사 구간이 콜 기준보다 높으면 콜 검토, 낮으면 폴드 검토, 겹치면 판단 보류다. 근사 구간은 equity ± 1.96 × standard_error이며 상대 범위 가정의 정확도를 나타내지 않는다. 추가 베팅 없는 쇼다운 가정을 안내 카드에 항상 표시한다.

메인 결과를 무효화하는 경로는 모두 Dashboard.clear를 거친다. 금액/카드/EV/행동 안내를 함께 제거하고 현재 상태에 맞는 다음 버튼을 제공한다. 숫자·카드 실패는 반복 status 메시지가 와도 구체적인 복구 문구를 유지한다. 캡처·포커 계산 알고리즘과 1초 목표 주기는 유지한다.

# 0.4: PokerNow 자동 인식

PokerNowRecognizer는 사용자 보정 프로필을 사용하지 않는다. 채도가 있는 큰 테이블을 찾고, 흰 카드 영역 안의 연결 성분에서 숫자와 무늬를 분리한다. 겹친 홀 카드는 하나의 흰 영역에 있어도 두 개의 숫자·무늬 쌍으로 읽는다. 숫자는 Tesseract의 서로 다른 페이지 분할 설정에서 일치하는 경우 채택한다. 무늬는 DejaVu/Liberation 표준 문자 글리프의 작은 래스터 마스크(폰트 파일이나 사이트 자산을 포함하지 않음)와 회전별 IoU를 비교하고 색상을 별도로 확인한다. 보드의 기하학적 카드 수와 판독된 수가 다르면 짧은 보드로 추측하지 않는다.

팟은 보드 위 중앙의 숫자, 스택은 앞/뒤 카드 옆의 숫자와 이름 줄을 함께 확인한다. 이름 줄은 영문 OCR 실패 시 픽셀 성분으로만 감지할 수도 있어 한국어 언어팩은 필요하지 않다. 글자 인식 자체로 닉네임을 확정하거나 저장하지 않는다. 전 화면 OCR, 숫자 크롭의 원본/확대 판독이 모두 일치해야 금액을 채택한다. 좌석 카드의 뒷면은 제보된 금색 테두리 배치를 우선 대상으로 하며, 접힌 카드/표시가 다른 테마는 정확도 검증이 더 필요하다.

제보된 테마의 활성 플레이어 패널 밝기로 내 차례 여부를 확인한다. GameState.hero_turn은 True/False/None이며, to_call도 미확인일 때 None이다. 상대 차례와 차례 미확인, CALL 미확인은 각각 다르게 안내하고 무료 체크로 채우지 않는다. 사전 선택 CHECK OR FOLD는 행동 근거에서 제외한다. 활성 CHECK/CALL 판단에는 같은 주 행동 행의 FOLD와 BET/RAISE/CALL 등의 표시가 필요하다. 카드와 상대 수가 읽히면 비용이 미확인이어도 equity는 계산하지만 팟 오즈·EV·금액 판단은 보류한다. D 표시가 충분히 확인될 때에만 제한적으로 BTN/헤즈업 BB를 부여하고 아니면 UNKNOWN이다.

AutomaticMonitorCapture는 선택한 한 모니터를 캡처하며 프레임마다 화면 크기를 받아 레이아웃을 다시 찾는다. Windows에서는 자기 프로세스의 표시 중인 창을 캡처 이미지에서 가려, 분석창의 수치/카드를 다시 입력으로 읽지 않게 한다. 최소화된 큰 창은 제외 처리하지 않는다. 자동 시작 시 큰 창을 최소화하고 작은 별도 분석창을 표시한다. 자신의 창 아래에 가려진 테이블을 복원하는 기능은 없으므로 작은 창은 빈 곳에 놓아야 한다. 실제 Win32 창 마스킹·DPI·mss는 Windows 수동 검증 대상으로 남는다.

자동 인식은 매 프레임 레이아웃/텍스트를 점검하되 숫자·카드 OCR은 픽셀 캐시를 쓴다. 계산 후 중요 영역과 카드/뒷면 기하를 재확인해 변한 결과는 버린다. 카드·보드·상대 수·범위·표본 수가 같으면 equity를 재사용해 금액/차례만 바뀔 때 불필요하게 재시뮬레이션하지 않는다. 캐시는 크기가 제한되어 있다. 모든 OCR은 로컬 실행이며 저장·전송·사이트 통신·클릭이 없다.

제공된 사진은 대화에서 육안으로 참고했으나 작업 파일로 노출되지 않아 원본 픽셀에 대한 자동 회귀 테스트는 수행하지 못했다. tests와 assets의 유사 레이아웃은 모두 자체 생성한 이미지다. 이 결과는 실제 사진·실제 사이트의 정확도 증명이 아니다.
